# 简历与面试材料

## 推荐定位

大数据运维工程师，具备 AI 工具接入、Python 自动化及服务部署实践。展示能够让 AI 在结构化约束内调用系统，并负责测试、上线及维护。

不要将本项目描述为大数据集群管理平台。其运维价值来自可迁移的工具集成、一致性与运行维护方法，尚未接入真实大数据平台。

## 简历项目描述

**AI 消费与物品管理助手｜个人项目｜Python / SQLite / MCP / Linux / systemd**

- 借助 AI 编程工具完成单用户自托管助手，封装 25 个 MCP 工具，支持自然语言驱动的库存、购买、退货及消费准则管理。
- 实现请求幂等、订单身份去重、严格参数校验、版本冲突检测与操作撤销，降低重复调用和误操作对数据的影响。
- 完成 130 项自动化测试，在 Ubuntu 云服务器部署服务，配置进程守护、健康与就绪检查、每日一致性备份和离线恢复，并验证 ChatGPT 远程调用。

只有本人确实理解并参与的内容才保留在简历中。不要填写未经测量的“提效百分比”“零故障”“高并发”等结论。

## 面试一分半介绍

“我的主业是大数据运维。这个个人项目用于验证 AI 如何接入真实工具，以及服务上线后怎样保证可维护。

用户通过自然语言描述购买、退货等意图，模型调用 MCP 工具。服务端使用严格参数模型、事务和版本校验处理事实变更，避免把模型输出直接当作数据库操作。

我关注三类问题：请求重试导致重复数据；误操作后的撤销和冲突；上线后的进程、健康状态与备份。项目有 25 个工具和 130 项测试，在 Linux 云服务器运行，并完成真实调用和恢复相关验证。

实现中使用了 AI 编程工具。我会具体说明自己的需求决策、方案审核和验证过程，并通过代码解释关键机制。后续希望把这些方法迁移到巡检和告警分析，但目前没有宣称已接入企业集群。”

## 需要能回答的问题

| 问题 | 讲解线索 |
| --- | --- |
| 为什么用 MCP？ | 为模型提供可发现的结构化工具；业务校验仍由服务端负责，协议本身不保证业务正确。 |
| 为什么不用 AI 直接操作 SQL？ | 缩小操作范围，校验字段、版本和业务约束，统一错误与审计记录。 |
| 幂等和订单去重有什么区别？ | 同一次请求重试与同一业务订单重复导入是两个维度。 |
| 怎么避免撤销覆盖后续更新？ | 保存变更快照并检查当前版本，不兼容时拒绝撤销。 |
| 为什么选 SQLite？ | 单用户、低并发、部署简单；规模扩大后需重新评估。 |
| 进程运行能说明服务正常吗？ | 不能；还需就绪检查与实际工具调用，进一步可增加业务探针。 |
| 备份成功能说明可恢复吗？ | 不能完全说明；校验与离线恢复测试是必要证据，仍需周期演练。 |
| 你如何使用 AI？ | 结合本人真实经历，区分需求与决策、生成实现、代码审核、测试及问题修复。 |

建议面试前亲自运行演示，沿 record_purchase → 写事务 → operations/operation_changes → undo 读一遍关键代码，并尝试独立修改一个小功能。
