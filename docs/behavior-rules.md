# 行为准则与阶段提醒

用户保存自己的日常流程与准则，由 ChatGPT 在需要时查询，并按实际阶段提醒。日常消费准则仍使用独立的数据表和工具。

本页所有安排均为虚构样例，不包含作者的个人作息。

## 一次交互

> 用户：我想休息一下，现在该做什么？
>
> 助手：你目前处于哪个阶段？
>
> 用户：收工前整理。
>
> 助手：按你保存的安排，现在归档演示资料。

阶段优先于参考钟点。当前阶段由用户明确或本次聊天上下文确认；建议过不等于已完成。流程中断后，只补问影响下一步的进展。进度和当天例外不持久化为行为打卡，也不承诺跨聊天延续。

## 数据与工具边界

| 长期保存 | 本次聊天 |
| --- | --- |
| 流程、适用星期、有序阶段 | 当前阶段和明确完成的事项 |
| 地点、状态、触发和必要时间条件 | 上次建议与中断信息 |
| 原文、行动、理由、替代方案、启停 | 带日期的当天临时例外 |

`routine_flows`、`routine_stages` 和 `behavior_rules` 保存长期配置；`behavior_candidates` 采用 satisfied / contradicted / unknown 三值条件判断。不同自然语言标签不会直接被当成互相矛盾，语义关系仍由模型结合原文判断。

阶段不明时，提醒结果隐藏可执行内容并给出 `next_question`；管理查询标记为 `management_only`，不能直接用完整准则清单替代当前提醒。明确阶段后，按已保存的行动提醒，不编造其他场景的方案。

## 通过对话修改

- “以后改为周三执行这套流程”：更新 `weekdays`；涉及多套流程时分别核对配置，不把临时例外写成长期变更。
- “暂停这个动作”：更新准则启用状态；保留原文和停用理由。
- “插入一个阶段”“把两个阶段调换顺序”：先生成服务端计划，再执行原范围。

阶段调整和多项导入使用 `preview_behavior_plan` / `apply_behavior_plan`。计划支持同批 `client_ref` 引用新流程、阶段和准则；全部动作在一个事务中提交，以一个 operation_id 撤销。删除有引用的流程或阶段默认拒绝，明确级联范围后才能预览和执行。

预览保存在有界内存，900 秒有效；当前对三张行为表采用保守的全行摘要检查，任意行为数据变化都要求重新预览。成功后的同键重试先返回持久化结果，即使服务已重启也不重复导入。失败全部回滚，后续引用或编辑阻止有冲突的撤销。

## 可复现证据

运行 `python portfolio_demo.py` 可看到虚构流程的批量预览、原子导入、阶段确认、适用星期修改和撤销。进一步阅读：

- `test_behavior_matching.py`：阶段、状态、时间条件和不确定性。
- `test_behavior_mcp.py`：严格嵌套参数、分页和 MCP 调用。
- `test_behavior_plans.py`：批量回滚、过期、重试、级联与撤销冲突。
- `test_migrations.py`：结构 1→2、校验、备份、失败回滚与旧历史保留。
